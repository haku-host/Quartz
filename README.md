# Вики Haku Host

Пользовательская документация: **https://wiki.haku.host**.

Сайт работает на Quartz 5. Исходники и готовая статика остаются в ветке `v4`: её использует существующая автоматическая синхронизация сервера. Имя ветки не обозначает версию движка.

## Локальная работа

Нужны Node.js 24 и npm 10.9.2 или новее.

```sh
npm ci
npx quartz plugin install --from-config
npx quartz build --serve
```

Статьи находятся в `content/`, настройки сайта и раскладки — в `quartz.config.yaml`, оформление — в `quartz/styles/custom.scss`. Плагины устанавливаются из npm и фиксируются в `package-lock.json`.

## Структура

| Каталог       | Содержание                                               |
| ------------- | -------------------------------------------------------- |
| `start`       | Первые шаги и выбор панели                               |
| `services`    | Выбор услуги и ресурсов                                  |
| `billing`     | Аккаунт, оплата, услуги, участники, единый вход и защита |
| `hakustack`   | VDS, питание, терминал, файлы, копии, доступ и защита    |
| `pterodactyl` | Игры и приложения, файлы, запуск, копии и доступы        |
| `minecraft`   | Java, миры, домены и плагины                             |
| `help`        | Диагностика и перенос проектов                           |
| `about`       | Адреса сервисов и сведения о вики                        |

Пишите по-русски, используйте понятные названия кнопок и проверяемые шаги. Для новых статей задавайте `title`, `description`, `modified: YYYY-MM-DD`. Пути файлов — на латинице в нижнем регистре. Внутренние ссылки: `[[billing/renewal|Продление услуги]]`.

При переносе страницы добавьте прежний путь в `aliases`. Карта прежних адресов хранится в `scripts/legacy-urls.json`. Не публикуйте секреты, данные аккаунтов и скриншоты с персональной информацией. Цены и доступность тарифов направляйте проверять в каталоге и форме заказа.

## Проверка и публикация

```sh
npm run check
npm test
npx quartz build
npm run check:wiki
```

`check:wiki` проверяет ссылки Markdown, выходные HTML-страницы, якоря и перенаправления старых адресов. Папка `docs/` содержит документацию движка и карты сверки статей с исходниками; в пользовательский сайт попадает только `content/`.

Workflow `.github/workflows/deploy.yml` проверяет изменения, собирает основной сайт и сохраняет `public/` в ветку `v4`. Контейнер синхронизации wiki.haku.host копирует эту папку из GitHub примерно раз в час.

Зеркало [haku-host.github.io/Quartz](https://haku-host.github.io/Quartz/) собирается отдельным заданием в `public-pages/` с `HAKU_WIKI_BASE_URL=haku-host.github.io/Quartz`. У зеркала свой префикс `/Quartz` для навигации, поиска, графа и ресурсов. Сбой сборки или публикации Pages не блокирует сохранение основного `public/`; зеркало не подменяет папку автосинхронизации.

Для проверки зеркала локально используйте отдельную выходную папку:

```sh
HAKU_WIKI_BASE_URL=haku-host.github.io/Quartz npx quartz build --output /tmp/haku-wiki-pages
```

Без этой переменной сборка использует `wiki.haku.host` из YAML. `check:wiki` проверяет основную сборку `public/` с этим адресом.

Граф справа доступен на статьях и страницах разделов: локальный показывает соседние статьи, кнопка раскрытия открывает полный граф. Для `@quartz-community/graph` 1.0.0 в `quartz.ts` есть узкий адаптер: он берёт текущий slug из `data-slug`, чтобы адреса вида `/billing/` не превращались в изолированные точки. Адаптер проверяет версию пакета и ожидаемый фрагмент скрипта и останавливает сборку при несовпадении. При обновлении плагина проверьте исправление upstream и удалите либо пересмотрите адаптер; вручную менять `node_modules` не нужно.

Для ручной публикации сначала выполните все проверки и включите результат сборки `public/` в коммит вместе с исходниками. Не исправляйте только файлы на сервере: следующая синхронизация заменит их версией из репозитория.

Обновление от 2026-10-01 использует Quartz 5.0.0, upstream `97a2d05`. Карты проверки функций — `docs/audit-*.md`.

Статьи о новых функциях сверены с развёрнутыми приложениями 2026-10-09: копии VDS, общий доступ, вход через биллинг, правила защиты и уведомления. Скриншоты тестовых услуг показывают интерфейс; подписи и аудиты отдельно отмечают операции, которые при съёмке не выполнялись.
