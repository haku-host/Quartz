Для подключения к VDS используйте **IP** из блока **«Детали»** на вкладке **«Обзор»** в [HakuStack](https://stack.haku.host). Проверяйте его заново после переустановки и других изменений услуги.

## Подключение по IPv4

Адрес из панели указывают в [[hakustack/ssh|SSH- или SFTP-клиенте]], настройках приложения и DNS-записи домена. Порт определяется программой внутри VDS: например, SSH-сервер и веб-сервер могут слушать разные порты.

HakuStack не заменяет настройку приложений в ОС. Чтобы сервис отвечал извне, он должен быть запущен, слушать нужный сетевой адрес и порт, а правила firewall — разрешать соответствующее подключение.

## Привязать домен

В панели DNS-провайдера, обслуживающего ваш домен, создайте запись **A** для нужного имени и укажите IPv4 из HakuStack.

Пример: для `app.example.com` запись `A` должна указывать на адрес вашего VDS. После этого настройте само приложение на обслуживание этого имени. DNS-запись не устанавливает веб-сервер и не выпускает HTTPS-сертификат.

При смене адреса обновите запись. Старое значение может оставаться в DNS-кэшах до истечения TTL, поэтому изменения не всегда видны сразу во всех сетях.

## Обратная запись PTR

PTR связывает IP с доменным именем. Для VDS Haku её управление находится **в карточке услуги биллинга**, в блоке **«Обратная DNS-запись (PTR)»**.

Откройте [[billing/domains|инструкцию по доменам и PTR]], чтобы проверить требования к имени, применить запись и учесть ограничение частоты изменений. Обычная запись A у вашего DNS-провайдера и обратная PTR в биллинге настраиваются отдельно.

## IPv6

В текущем пользовательском интерфейсе HakuStack нет отдельного раздела выдачи и настройки IPv6. Из наличия вкладки сети или IPv4 нельзя сделать вывод о выделенном IPv6.

Если вашему проекту нужен IPv6, уточните его доступность для конкретной услуги через [[help/index|поддержку]]. Для настройки понадобятся выданные вам адрес, префикс и параметры маршрутизации. Запись **AAAA** создавайте только для действительно выделенного и настроенного IPv6.

## Если сервер или приложение недоступны

1. Проверьте IP и [[hakustack/power|питание сервера]]. Убедитесь, что услуга не заморожена.
2. Откройте [[hakustack/console|терминал или SPICE]]. Если консоль работает, проверьте состояние приложения внутри ОС.
3. Проверьте, что приложение слушает ожидаемый порт и внешний адрес, а не только `127.0.0.1`.
4. Проверьте разрешения firewall для нужного порта. Не отключайте все правила ради проверки одного сервиса.
5. Если подключение по IP работает, а по имени нет, проверьте DNS-запись и доменную конфигурацию приложения.

В Linux с установленным `iproute2` полезны команды просмотра:

```sh
ip address
ip route
ss -lntup
```

Они показывают адреса интерфейсов, маршруты и слушающие TCP/UDP-сокеты. Команды выполняются внутри вашего VDS и не меняют сетевые настройки.

График **«Скорость сети (Мбит/с)»** помогает увидеть обмен данными, но отсутствие трафика не доказывает неисправность сети. Объяснение показателей есть в [[hakustack/monitoring|статье о диагностике]].
